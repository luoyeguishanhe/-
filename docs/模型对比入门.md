# 从录音到模型对比：入门说明

这套工具让同一份录音分别经过 small 和 medium，保存它们的文字与耗时。它使用已经训练好的 Whisper 模型进行识别，不会重新训练模型，也不需要翻译 API 密钥。下载模型需要网络；模型下载后，识别在本机 CPU 上运行。

## 先认识流程中的几个东西

```text
同一份 WAV → 相同的语音切段 → small → 文字、每段耗时
                           → medium → 文字、每段耗时
参考 TXT（与录音逐字对应）───────────→ 错字、漏字、多出字
```

- **模型**：别人已经训练好的识别程序和参数。small、medium 是两种规模；更大通常更费资源，是否更准需要实际测试。
- **推理**：让模型读取录音、输出文字。我们这次做的是推理和比较。
- **VAD**：判断哪些地方可能有人说话，把音频分段；配乐有时也会被误判。工具先用现有 WebRTC 切段，再由 Whisper 内部的 Silero 过滤片段中的非语音。
- **参考原文**：专门用来检查模型的答案。网上文章必须裁到录音实际读出的范围，删节、重复、口误或录音截断都要按声音处理。
- **简体转换**：中文结果经过 OpenCC，避免“漢語”和“汉语”被当作不同答案。
- **CPU / GPU**：CPU 是电脑的主处理器，GPU 通常是显卡的计算单元。本轮统一用 CPU，避免把硬件不同造成的差距算到模型头上。
- **int8 / 线程**：int8 是一种节省计算和内存的数值格式；4 个推理线程表示模型使用的计算线程数。两种模型设置相同即可，初次使用不用调整。
- **beam size / temperature**：前者控制模型保留多少个文字候选，后者控制随机采样。本轮固定候选数为 5、temperature 为 0，不使用随机采样回退。

## 第一次要准备什么

1. 录音放在项目目录或其他本地路径。工具当前要求 16 kHz、单声道、16 位 PCM WAV，与应用保存的格式相同。
2. 参考文字放到 `benchmark-data` 文件夹，每个音频对应一个 UTF-8 TXT。TXT 中只写实际说出的字，不加时间码和说明。
3. 复制 `benchmark.example.json`，命名为 `benchmark.local.json`，填写录音与参考文字路径。本次已为 D 盘两份录音准备好，无需从头填写。

清单中的主要字段：

| 字段 | 用途 |
| --- | --- |
| `id` | 文件内部使用的唯一英文编号，例如 `baiyang` |
| `label` | 报告显示的中文名称 |
| `audio` | 原始录音路径；相对路径从清单所在文件夹开始找 |
| `evaluation.reference` | 参考 TXT 的路径 |
| `evaluation.status` | `draft` 是待核对草稿，`verified` 是你已听录音逐字核对 |
| `evaluation.start/end` | 只给原录音这个时间范围评分；该范围之外的文字仍会保存 |
| `evaluation.source_url` | 查找原文时用的网址，方便核对版本 |

如果没有参考文字，删掉整个 `evaluation` 项，也可以先比较文字和耗时。评分边界需要在语音片段之间，不能截断一个模型输入片段；工具遇到这种情况会显示“未评分”。

## 怎样开始对比

双击项目根目录的 `compare-models.cmd`。它会寻找当前目录里的 `.venv` Python 和 `benchmark.local.json`，依次运行 small、medium，把结果放进 `benchmark-results` 下的新文件夹。

第一次缺少模型时会下载，后续复用缓存。程序不会替换原 WAV。每次运行都会创建新的结果目录，不覆盖上一轮。

如果想在 PowerShell 中运行同样的过程，先进入项目目录，例如：

```powershell
cd D:\subtitle-app
.venv\Scripts\python.exe -m subtitle_app.benchmark --manifest benchmark.local.json --models small medium
```

这条命令中：

- `.venv\Scripts\python.exe` 是项目使用的 Python。
- `-m subtitle_app.benchmark` 让 Python 运行项目里的模型对比模块。
- `--manifest` 后面是样本清单。
- `--models small medium` 指定要比较的模型。

只想测试一个模型，可以用 `--models small`；已经下载好模型而且不想联网时，加 `--local-files-only`。两种模型都会固定在 CPU、int8、4 个推理线程上运行，依次处理，避免相互抢占计算资源。

## 报告怎么看

打开本次结果目录中的 `report.html`，浏览器能显示汇总表、录音播放器、逐段识别文字和逐字差异。

| 文件 | 你能用它做什么 |
| --- | --- |
| `report.html` | 最方便的阅读入口，可以播放原录音 |
| `report.md` | 同样内容的文字版 |
| `summary.csv` | 用 Excel 查看汇总，CER 以小数保存，0.05 表示 5% |
| `mingchao-small.txt` 等 | 一个模型的完整识别文字 |
| `*-timed.txt` | 带原录音时间的逐段文字，空结果也保留标记 |
| `results.json` | 完整配置、模型版本、录音哈希、每段文字、推理时间和逐字错误 |
| `manifest-snapshot.json` | 当时使用的清单，方便追溯测试配置 |

**字错误率 CER**：`（替换字数 + 漏字数 + 多出字数）÷参考字数`。例如参考有 100 字，其中错 4 字、漏 2 字、多出 1 字，CER 就是 7%。它越低越好；如果凭空生成很多文字，也可能超过 100%，所以不能简单把 `100% - CER` 当作准确率。

评分先统一简繁、全半角和大小写，去掉标点与空白；阿拉伯数字和中文数字没有自动等价。例如 `1344` 和 `一三四四` 可能被算成差异，要在报告中检查它们是否只是数字写法不同。

**RTF**：`识别耗时÷录音时长`。例如 60 秒录音处理了 12 秒，RTF 为 0.2。它不包含下载、加载、预热、切段，也不等于字幕出现的实际延迟。实时字幕还要等当前片段结束，而当前切段最长为 15 秒。

**待核对草稿**：网上原文可能与声音不同。参考还标记 `draft` 时，报告中的 CER 只是暂时对照值，不能拿来宣称模型的真实准确率。

## 校对后怎样重新评分

1. 用浏览器里的播放器或其他播放器，听清楚评分范围对应的声音。
2. 修改 `benchmark-data` 中的参考 TXT，确保它只包含实际说出的字，不要把模型猜出的字当作正确答案。
3. 在 `benchmark.local.json` 中，把该段的 `"status": "draft"` 改成 `"status": "verified"`。
4. 重新评分。例如本次结果目录是：

```powershell
.venv\Scripts\python.exe -m subtitle_app.benchmark --manifest benchmark.local.json --score-only benchmark-results\20261020-small-medium
```

这个过程读取已经保存的识别文字，通常很快，不会重新下载或运行模型。重新评分前会保存旧结果 JSON；也会检查录音哈希，防止误把另一份录音配上旧识别结果。

## 程序内部是怎样实现的

| 文件 | 职责 |
| --- | --- |
| `src/subtitle_app/recognition.py` | 加载模型，使用共同识别参数，转换为简体中文；实时窗口和模型对比都调用它 |
| `src/subtitle_app/speech_pipeline.py` | 将录音分段，并在后台识别，让窗口保持响应 |
| `src/subtitle_app/benchmark.py` | 读清单和 WAV、固定相同输入、依次调用模型、计时并生成报告 |
| `src/subtitle_app/evaluation.py` | 对齐参考和识别文字，统计替换、漏字和多出字 |
| `compare-models.cmd` | 双击入口，替你调用 Python 模块 |

为了便于复现，共同识别代码固定 `temperature=0`，关闭随机采样回退。模型参数和版本都写入结果 JSON。文件中的片段起止时间是原录音位置，不是字幕已经逐字校准的时间轴。

第一轮先比较 small、medium，暂不根据两份音频就决定全局最优模型。还需要校对参考文字、加入未调参的新音频，然后再比较中文专用模型或调整切段方式。
