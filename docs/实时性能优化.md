# 实时 GPU 识别与积压控制

系统声音识别与直播翻译会自动尝试 NVIDIA GPU / float16。启动前不仅检查显卡，还加载模型并执行一次 GPU 推理，验证 CUDA 运行库实际可用。无法使用时回退 CPU / int8；运行中遇到 GPU 推理错误时也会尝试 CPU 重识别当前片段。状态栏显示实际后端，鼠标悬停可查看回退原因。首次模型下载或加载失败仍会正常报错。

GPU 便携版随包提供 CUDA 12 的 cuBLAS、cuDNN 和 NVRTC；电脑需要兼容的 NVIDIA 驱动，但不需要自行安装 Python 或 CUDA Toolkit。显卡也可能同时被播放器、游戏或 Ollama 占用，GPU 不保证任何情况下都能保持相同耗时。

源码开发环境可运行：

```powershell
.venv\Scripts\python -m pip install -e ".[gpu]"
.venv\Scripts\python -m subtitle_app
```

直播模式的变化：

- 约 0.5 秒静音或最长约 4 秒分段；使用 beam size 1，关闭逐词对齐和内部重复 VAD。与完整识别参数相比可能产生不同文字，精确字幕校对继续使用文件模式。
- 识别只保留一个等待片段，翻译只保留一条等待文字。慢处理时替换最旧的等待项，避免积压几十秒；因此直播识别可能漏段，并有明确提示。
- 正在处理的识别或请求无法即时中止，等待队列限制不能消除本次计算或接口超时。网络服务很慢时仍可能有明显翻译延迟。
- 等待下一条翻译时保留上一条原文和译文，两者一起更新，避免显示互不对应的句子。
- 状态栏分别显示后端、识别耗时、排队时间、识别落后录音的秒数、翻译耗时及跳过数量。停录后仍处理保留下来的最后一段。

文件模式和原有基准测试继续使用 CPU 与完整识别参数，不丢弃文件片段。直播原文导出使用片段时间，文件模式仍使用逐词时间戳。

## 本机样本验证

2026-10-24，在 RTX 5060 系列显卡上，使用本地 `entest1.wav` 前 8 秒、Whisper small、指定英语，各配置预热后识别一次：

| 配置 | 识别耗时 | 处理耗时 / 音频时长 |
| --- | ---: | ---: |
| 原 CPU / int8，完整识别参数 | 1.346 秒 | 0.168 |
| CPU / int8，实时参数 | 1.111 秒 | 0.139 |
| GPU / float16，实时参数 | 0.137 秒 | 0.017 |

这是单个英文样本的识别阶段对比，不含分段等待、翻译接口和界面更新时间，不代表其他语言、视频或电脑上的固定速度。该片段三次输出的词语一致，仅大小写有差异；没有据此计算总体准确率。

复现脚本接受 16 kHz、单声道、PCM16 WAV，不上传录音。报告包含该片段的识别文字，请自行保管：

```powershell
.venv\Scripts\python packaging\check_live_performance.py --audio 录音.wav --model 本地small模型目录 --report performance.json --language en
```

打包后可严格检查 CUDA，失败时不会把 CPU 回退算作 GPU 成功：

```powershell
& .\巴别塔.exe --self-test gpu-check.json --device cuda --live --audio 中文录音.wav
```
