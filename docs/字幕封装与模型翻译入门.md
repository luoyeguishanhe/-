# 字幕封装与外部模型翻译

## 现在可以做什么

流程是：**视频 → small 识别原文 → 校对 → 外部模型翻译 → 导出译文 SRT → 封装 MKV**。

也可以直接使用已准备好的视频和 UTF-8 SRT，从“翻译与封装…”进入，无需再识别。

这里有两种不同的模型：

| 模型 | 输入 | 输出 | 运行位置 |
| --- | --- | --- | --- |
| Whisper small | 音频 | 原声语言的文字和时间 | 当前在本机 CPU |
| 翻译大模型 | 字幕文字 | 目标语言的译文 | 你选择的云端或本地服务 |

## 一、先把已有字幕放进视频

1. 启动更新后的程序。
2. 主窗口点击“翻译与封装…”。有本次识别字幕时会带入；使用旧字幕则点击“导入 SRT…”。
3. 点击“选择视频…”，选择字幕对应的原视频。
4. 下拉框选择“原文字幕”。
5. 点击“封装为带字幕的 MKV…”，选一个新文件名。
6. 完成后用支持 MKV/SRT 的播放器打开，找到字幕菜单，选择新字幕轨。字幕可以关闭。

如果刚校对过，应从校对窗口的“翻译与封装…”进入，这样会带入修改后的文字和时间。主窗口的同名按钮带入的是原识别结果。

### “封装”实际做了什么

可以把 MKV 理解为装轨道的盒子：程序将原视频画面、全部音轨和当前字幕放进一个新盒子。视频音频直接复制，所以不重新压缩画面。字幕仍是独立的文字轨道，可开关。

程序使用随 Python 依赖安装的 FFmpeg 运行该任务，命令通过参数列表传入，不需要你手动执行。没有修改原视频，没有把字幕画进每一帧。

此版本输出 MKV，只放入当前选中的一条字幕，不保留源文件旧字幕轨和附件；保留可复制的章节及元数据。如果编码不适合直接装进 MKV，会显示原因，不自动转码。Windows 自带播放器支持情况因版本而异，可用 VLC 等支持 MKV/SRT 的播放器。

## 二、使用千问云端翻译

选择“千问云端（中国内地）”，程序预填：

| 项目 | 内容 |
| --- | --- |
| 接口地址 | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 模型名称 | `qwen-plus` |
| API Key | 填入你在对应服务开通的 Key |
| 目标语言 | 简体中文 |

模型权限、额度和地区由服务提供方决定；其他地区的 Key 可能需要不同地址，应以服务控制台为准。程序不内置免费额度，也不会自动创建账号。**千问云端模型和本地千问模型是不同的运行方式。**

点击“开始翻译原文字幕”后，程序会把字幕文字发到你填写的地址。视频和声音不会上传。API Key 只留在当前工具窗口的内存里，不存到文件，也不写日志；关闭工具窗口后需要重新填写。修改服务地址会清空已填 Key。

## 三、使用本机 Ollama 运行千问

先安装并启动 Ollama，在 Ollama 中准备一个模型。示例模型名称是 `qwen2.5:7b`，可以通过它的界面或以下命令下载：

```powershell
ollama pull qwen2.5:7b
```

这一步会下载较大的模型文件，请按自己的机器选择模型大小；本应用不会替你下载 Ollama 模型。

在本应用选择“Ollama 本地”，预填地址为 `http://127.0.0.1:11434/v1`。模型名要与 Ollama 中已准备的名称完全一致，通常不需要 Key。`127.0.0.1` 表示你自己的电脑。服务必须处于运行状态，才能收到请求。

本地运行不按云端 token 计费，但需要机器资源。“免费额度的云端接口”能否使用，取决于该服务是否提供兼容接口及可用额度。

## 四、模型怎么被 Python 调用

### 第一步：只给字幕编号和文字

例如程序发送：

```json
[{"id": 1, "text": "Hello, everyone."}, {"id": 2, "text": "Welcome back."}]
```

程序通过 HTTP POST 请求 `接口地址/chat/completions`，告诉服务模型名称和翻译目标。默认一批 12 条，用后台线程等待结果，窗口仍可操作取消。

### 第二步：模型按编号返回译文

要求模型返回：

```json
{"translations": [{"id": 1, "text": "大家好。"}, {"id": 2, "text": "欢迎回来。"}]}
```

即使返回顺序变了，程序也按编号匹配。遗漏、重复编号、空文字或截断输出会报错，整批不采用。不会用缺失的译文覆盖原字幕。

### 第三步：程序复制原时间

开始和结束时间始终留在本地。例如原文显示时间是 2.5～4 秒，译文仍显示在 2.5～4 秒。目标为简体中文时，另做繁转简，并按字幕宽度换行。

这能保留时间轴，但不能修正原始识别的时间误差，也不保证译文自然程度；仍建议试听核对。

### 第四步：保存或封装

完成后下拉框自动选到“译文字幕”。点击“另存译文 SRT…”保存独立字幕，或点击“封装为带字幕的 MKV…”生成新视频。

原文和译文分开保留，已有文件不覆盖。翻译被取消或某批失败时，之前已完成的译文保留，可另存 `partial` 文件；未完成的译文暂不允许封装，以免误认为整部视频已有完整翻译。

## 五、常见情况

| 提示 | 检查什么 |
| --- | --- |
| 无法连接或超时 | 地址是否正确；本地服务是否已启动；模型是否准备好；网络是否可达 |
| HTTP 401 | Key 是否正确，是否填在 API Key 栏 |
| HTTP 403 / 404 | 账号是否有模型权限，模型名和地区地址是否匹配 |
| HTTP 429 | 服务额度或调用频率限制 |
| 译文编号或格式错误 | 减少每批条数，或使用更能遵循 JSON 格式的模型 |
| 取消后还在等待 | 当前 HTTP 请求需返回或超时，最长约 90 秒，之后不会发下一批 |

不自动重试，避免重复提交造成额外调用。再次开始翻译会从头处理；已完成的结果请先保存。目前仅统计当前翻译任务中服务返回的 token，未返回时标为未知；**未实现价格计算或跨任务累计账单**。

## 六、代码分工与验证范围

| 文件 | 作用 |
| --- | --- |
| `subtitles.py` | 读取 UTF-8 SRT、检查时间、导出字幕 |
| `subtitle_mux.py` | 调用 FFmpeg 复制视频音轨，加入软字幕，保护原文件 |
| `translation.py` | 配置接口、发送请求、校验译文、保持时间、统计返回用量 |
| `background_job.py` | 后台线程、取消标记、结果事件 |
| `subtitle_tools.py` | 选择文件、填写服务参数、展示进度和处理结果 |

69 项测试通过，包含真实 FFmpeg 封装、音视频压缩数据比较、字幕时间核对，以及通过本机模拟 HTTP 服务完成“请求 → 译文 SRT → MKV”的窗口流程。模拟响应只用于验证接口和程序逻辑，**不代表已经调用真实千问或验证翻译质量**。真实服务需要你配置后试用。

此轮为识别完成后的批量翻译，尚未把翻译接到实时录音的逐句流水线；字幕烧录、EXE 打包、费用计算也未在本轮加入。
